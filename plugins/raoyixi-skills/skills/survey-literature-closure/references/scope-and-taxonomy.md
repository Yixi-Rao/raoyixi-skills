# 范围契约与判定分类

## 1. 先把目标变成可证伪问题

记录以下内容并在首轮抓取前冻结：

- 研究问题：最终要支持什么判断、设计或统计？
- 截止日期：按论文首次公开日期截断，而不是以后发表的会议日期。
- 分析单位：论文、技术报告、数据集、系统或代码仓库。
- 输出字段：每个字段的定义、证据来源和规范化粒度。
- 完成语义：有限清单、相关子图闭包或快速扫描。

若中途改变严格条件、截止日期或来源集合，创建新契约版本，使已有判定失效并重新筛选受影响节点。

## 2. 把纳入规则写成谓词

将核心定义拆成独立、可由原文回答的必要条件。例如：

```text
C1：论文是否提出或实证研究目标机制？
C2：该机制是否发生在用户指定的阶段或场景？
C3：是否满足指定的训练、推理、系统或数据边界？
core = C1 AND C2 AND C3
```

为每个谓词保留 `true / false / unknown`，并记录证据位置。不要用标题关键词代替谓词判断。

## 3. 使用四类终局

- `core`：全部必要谓词为 `true`。
- `adjacent`：至少一个必要谓词为 `false`，但机制或问题设置足够接近，继续扩展有发现价值。
- `excluded`：明确落在范围外，且不需要继续沿该分支发现论文。
- `unresolved`：任一关键谓词为 `unknown`、身份冲突或完整原文不可得。

只有 `excluded` 是叶子。`unresolved` 不是“低相关”的同义词；它必须阻止完成声明。

## 4. 控制邻接边界

把邻接规则写成正面条件，不要把“所有非核心”都归为邻接。至少说明：

- 与核心问题共享什么机制、输入、训练信号、系统环节或评估目标；
- 为什么该节点的引用邻域仍可能包含核心论文；
- 哪些看似相关但应直接排除的分支不会继续扩展。

在第一次批量筛选后抽样校准判尺；若两名判读者无法稳定复现分类，先修订契约再扩大队列。

## 5. 建立多来源种子

至少组合两类种子：

- 用户或领域专家给定的已知论文；
- 题名/摘要/作者/关键词检索结果；
- 已知综述、基准或代表系统中的参考文献；
- 目标表格或知识库中的既有记录。

记录每个种子的来源、检索式、检索时间和原始标识。种子不是自动核心；仍需全文判读。

默认要求至少两类独立 provenance，例如专家给定种子与关键词检索、既有表格与综述参考文献。若题材只能从单一入口启动，在契约中显式把最低来源类别设为 `1`，并将潜在断连分支写入覆盖限制。

## 6. 不预设结论性分类

先阅读论文和系统，再从机制归纳二级主题。不要因为当前流行就预先套用 Agent 角色、RAG、Planner/Executor 或固定工具链分类。二级主题可以迭代，但核心纳入谓词变化必须版本化。
